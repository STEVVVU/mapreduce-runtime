# Benchmark path

The maintained driver is `tools/benchmark.mjs`. `node --test tools/benchmark.test.mjs` checks deterministic data and nearest-rank statistics. `node tools/benchmark.mjs smoke` launches a real coordinator and two separate worker processes, submits one warm job and one checked job, compares HTTP and durable results against an independent word-count oracle, and reaps every child. This is a correctness smoke, not a performance result.

`node tools/benchmark.mjs benchmark` requires an isolated Linux runner. Workload version 1 freezes seed 421, 256/2048 records with sixteen words, 128-word vocabulary, 0/90% hot-key skew, eight splits/four reducers and 1/2/4 workers. Five repetitions alternate worker order; each fresh-store cell has one untimed warm job and six sequential measured jobs. Baseline is one worker with the identical partitions and data. Rate sweeps offer 0.5/2/8 jobs/s for ten seconds against four workers. Scheduled arrival remains the latency origin. At most 32 jobs may be outstanding; excess offers are recorded as generator declines, never silently omitted. Job deadlines are 60s and HTTP calls retain the real client's 5s deadline. The highest rate with zero losses, dispatch-p99 below 100ms and job-p99 below 5s receives a 120s stability run. No qualifying rate explicitly blocks stability. A separate delayed-count job kills an observed assigned worker and checks retry publication and exact output.

`node tools/benchmark.mjs profile` diagnoses the frozen 256-record, 90%-skew, four-worker, 8jobs/s, 120s stability cell with fresh accumulating state and CPU profiling enabled. This matches the workload that showed degradation in the first hosted baseline. Profiles are separate diagnostic runs and cannot support performance comparisons. Child profile completeness is asserted before success; inspect the retained `.cpuprofile` files before attributing a hot path.

Every cell stores raw scheduled/start/finish timestamps, outcomes, input/output hashes, logical accepted shuffle bytes, attempts, publications and Linux `/proc` CPU ticks/RSS every 100ms for each child and the generator. Convert CPU ticks using the recorded `CLK_TCK`; absent Windows process counters are null in smoke evidence. Polling can add 20ms plus event-loop lag to completion observation. Shuffle bytes exclude HTTP framing and retries. Fresh stores are retained under ignored `.runs/benchmark-*`; no scratch deletion occurs. `summary.json` retains environment/source/dirty status and trial results. Results are only valid with `cleanup:true`, exact oracle equality and all offered work accounted for.

The manual `Benchmark` workflow runs smoke plus the selected campaign on a separate ubuntu-24.04 runner with a 45-minute cap. Main owns dispatch and artifact review. No speedup or production SLO follows from a smoke or unprofiled raw result.
